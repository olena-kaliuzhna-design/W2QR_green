Security Model

W2QR’s threat model, key lifecycle, and honest trade-offs.

Threat model

W2QR protects against an attacker who obtains your QR code — whether by stealing the paper, intercepting a photo, or accessing your cloud storage. The attacker may also have unlimited computing resources to brute-force passwords.

W2QR does not protect against:

  • Malware on your device at the time of encryption or decryption
  • Shoulder surfing / someone watching you type your password
  • A compromised browser or operating system

No password verifier

This is W2QR’s strongest security guarantee. There is no stored hash, MAC, known plaintext, AEAD tag, wallet address, or any other artifact that lets someone check if a password is correct without going to the blockchain.

Every password decrypts to a valid BIP-39 seed phrase. To find the real one, the attacker must derive wallet addresses from each candidate and check them on-chain — economically infeasible at scale.

Client-side only

All cryptographic operations happen in your browser. The W2QR server never receives:

  • Your password
  • Your seed phrase (mnemonic)
  • Your private keys
  • Your wallet addresses

All encryption and decryption runs in your browser. The W2QR server never stores or receives your password, seed phrase, private keys, or wallet addresses.

Key lifecycle

Creation

Keys are derived in the browser using Argon2id (WASM) and HKDF-SHA-256. All key material is held in memory only during encryption and decryption.

Storage

Your encrypted QR contains only ciphertext. Optional Google Drive backup stores the same ciphertext. The W2QR server stores no wallet secrets.

Zeroization

Derived keys and intermediate buffers are zeroed in memory after use. JavaScript does not guarantee immediate memory clearing, but explicit zeroization defends against heap dumps and inspector tools.

Rotation

If you suspect your password may be compromised, create a new encrypted QR with a new password. Transfer your assets to a new wallet generated from a fresh seed phrase for maximum security.

Honest trade-offs

vs. Hardware wallets

A hardware wallet stores keys in a secure element — stronger physical security. W2QR stores keys as encrypted QR codes — more portable and no hardware dependency. Neither is strictly better; they serve different needs.

vs. Metal seed plates

A metal plate survives fire and water. An encrypted QR survives being photographed or emailed — the encryption protects it. W2QR is a complement to metal backups, not a replacement.

vs. Cloud wallets (exchanges)

An exchange holds your keys for you — convenient but custodial. W2QR is always non-custodial: your keys are never on any server in usable form.

Rate limiting

Server-side API routes are rate-limited per IP address. All access attempts are audit-logged. All error messages are generic — the server never reveals whether an operation succeeded or failed for security reasons.

W2QR Cards — plausible deniability

A W2QR Card contains random bytes that become a wallet only when combined with a password through honey encryption. Every password produces a valid BIP-39 mnemonic — the card itself does not “belong” to any particular wallet until activated.

An attacker who steals a card cannot determine which password was used to activate it. There is no hash, MAC, AEAD tag, or any verifier that reveals the correct password. The only way to identify the real wallet is to derive addresses from each candidate mnemonic and check balances on-chain — economically infeasible at scale.

All errors return the same generic message: “Unable to unlock this W2QR. Check your credentials.” There is no way to distinguish a wrong password from a card that was never activated.

Plastic card activation security

A pre-printed plastic card uses honey encryption. After activation with your password, you can optionally back up to Google Drive. The physical card’s QR does not change during activation — it remains usable with the same password.

W2QR also supports a password QR card: print your strong password as a separate QR on a second plastic card. Keep the wallet card and the password card in different locations — together they open your wallet, apart each is useless to an attacker.
